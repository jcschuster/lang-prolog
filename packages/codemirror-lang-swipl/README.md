# codemirror-lang-swipl

[SWI-Prolog](https://www.swi-prolog.org) language support for
[CodeMirror 6](https://codemirror.net/): a Lezer parser for SWI-Prolog 7+ syntax, with
highlighting, indentation, folding and completion of built-in predicates.

```js
import {EditorView, basicSetup} from "codemirror"
import {prolog} from "codemirror-lang-swipl"

new EditorView({extensions: [basicSetup, prolog()], parent: document.body})
```

`prolog()` returns the `LanguageSupport`; `prologLanguage` is the `LRLanguage`.

## What it parses

The operator and built-in tables come from SWI-Prolog 10.0.2 (see `spec/prolog/SOURCE`
in the repository).

**Operators are not parsed.** Prolog programs change the operator table at run time with
`op/3`, so no fixed grammar can build the right term for every program. This parser
reads tokens and the structure that does not depend on operators: clauses and their
end, the neck (`:-`, `-->`), compound terms, lists, curly terms, dicts and parentheses.
Between those, terms are flat sequences: `X is A + B` is `Variable Operator Variable
SymbolAtom Variable`. Operators declared in the edited file still tokenise; they are
just not highlighted as operators.

Each clause is a `Directive`, `Rule` or `Fact` ending in `End`. The name of a clause's
head is in `HeadFunctor` (after an optional `Module:`), the name of every other compound
in `Functor`, followed by `ArgList`. Names are told apart by the tables: `Operator`
(alphanumeric operators such as `is`, `mod`), `Control` (`->`, `\+`, `call`, `true`,
...), `DirectiveName` (`dynamic`, `use_module`, ...), `Builtin` (other built-in
predicates, by name only), and plain `Atom`. `f(` is a compound and `t{` a dict, `f (`
and `t {` are not, as in SWI-Prolog. Block comments nest, as in SWI-Prolog.

The parser is more lenient than SWI-Prolog: it accepts some input that SWI-Prolog
rejects (`X(a)`, digits out of range for their radix, unknown escapes). It only
recognises ASCII digits in numbers, and a digit group split by a comment
(`1_000_/*c*/000`) is not one number to it.

The tests check every token class and clause kind, and parse the `.pl` files of
SWI-Prolog's own library: each file that SWI-Prolog's reader accepts must parse without
error nodes and into as many clauses as SWI-Prolog reads terms. Exceptions are listed in
`test/KNOWN.md`.

## Files

Generated by `pnpm generate` (`gen/tables.mjs` in the repository) from a run of the
pinned `swipl`: `src/tables.ts`, and in the repository `spec/prolog/ops.json`,
`spec/prolog/builtins.json` and `spec/prolog/SOURCE`.

Hand-written: `src/prolog.grammar`, `src/tokens.js` (the tokenizer for names, symbol
characters, clause ends, nested comments and quasi-quotations), `src/highlight.ts`,
`src/index.ts`, the tests, and in the repository `spec/prolog/control.json` (the control
constructs and directive names, which `pnpm generate` checks against the generated
tables) and `tools/`.
